NACA 4-DIGIT AIRFOIL GENERATOR

Turns a four-digit NACA code into wing-section coordinates, ready for analysis software or for cutting wing ribs. Written in MATLAB, rebuilt here so it runs in your browser.

Project introduction

A NACA 4-digit code describes a wing cross-section in four numbers: how much the section is curved (camber), where that curve peaks, and how thick it is. This tool turns the code into surface coordinates, plots the section, and exports a point file that XFOIL, XFLR5 or CAD software can open.

Try it: type a code or pick an example, and the plot updates as you go.

Major design choices

  • Cosine point spacing. Points sit at \(x = 1 - \cos\varphi\) instead of evenly along the chord. The nose has the tightest curvature and matters most to analysis codes, so points cluster there; the nearly straight rear needs fewer. Evenly spaced, 41 points leave the nose of a 12 % section visibly faceted.
  • Thickness applied perpendicular to the camber line. This is the true NACA definition. Adding thickness straight up and down is simpler but shifts the nose and changes its radius on cambered sections.
  • Open or closed trailing edge. The original equation leaves a small gap at the tail (0.25 % of chord for a 12 % section), which matches published NACA data. One coefficient change closes it with the smallest change to the shape, which CAD lofts and meshing tools need.
  • Two export formats. The .dat file is normalised to unit chord in the order XFOIL and XFLR5 expect (tail → upper surface → nose → lower surface → tail). The .csv is scaled to the chosen chord length for CAD.
  • Left out: other NACA series. The 5-digit and 6-series families depend on tabulated constants. The 4-digit family covers most model aircraft, small drone and teaching use, so it was the best return for the effort.
  • Left out: aerodynamic analysis. XFOIL and XFLR5 are free and well validated. Writing a solver would add risk without adding accuracy, so the tool focuses on clean geometry for them.

Design

The generator follows the standard NACA 4-digit equations (Abbott & von Doenhoff). All lengths are fractions of the chord until the final scaling step.

Read the code
\[ m = \frac{d_1}{100}, \qquad p = \frac{d_2}{10}, \qquad t = \frac{d_3 d_4}{100} \]
Point spacing
\[ \varphi_i = \frac{(i-1)\,90^\circ}{N-1}, \qquad x_i = 1 - \cos\varphi_i \]
Thickness
\[ y_t = 5t\left(0.2969\sqrt{x} - 0.1260\,x - 0.3516\,x^2 + 0.2843\,x^3 + a_4 x^4\right) \] \[ a_4 = -0.1015 \ \text{(open)} \quad\text{or}\quad {-0.1036} \ \text{(closed)} \]
Camber line
\[ y_c = \begin{cases} \dfrac{m}{p^2}\left(2px - x^2\right) & 0 \le x < p \\[8pt] \dfrac{m}{(1-p)^2}\left(1 - 2p + 2px - x^2\right) & p \le x \le 1 \end{cases} \]
Camber slope
\[ \frac{dy_c}{dx} = \begin{cases} \dfrac{2m}{p^2}\,(p - x) & 0 \le x < p \\[8pt] \dfrac{2m}{(1-p)^2}\,(p - x) & p \le x \le 1 \end{cases} \qquad \theta = \arctan\frac{dy_c}{dx} \]
Surfaces
\[ \begin{aligned} x_U &= x - y_t\sin\theta, & y_U &= y_c + y_t\cos\theta \\ x_L &= x + y_t\sin\theta, & y_L &= y_c - y_t\cos\theta \end{aligned} \]
Scale to chord
\[ (X,\ Y) = c\,(x,\ y) \]
  • Symmetric sections skip the camber step. When the first digit is 0 the camber line is zero everywhere, which also avoids dividing by \(p = 0\).
  • The code is read as text, so 0012 keeps its leading zeros. Codes that can't exist, such as 2012 (camber with no position for it), are rejected with a clear message.
  • The nose point is written once. Both surfaces start at the same leading-edge point, so the export skips the duplicate that would otherwise create a zero-length panel in XFOIL.

Results

Each output was checked against the property the code is meant to describe:

  • NACA 0012: maximum thickness of 12.00 % of chord, at 30 % chord.
  • NACA 2412: camber line peaks at 2.00 % of chord at 40 % chord, with the slope continuous where the two camber equations meet.
  • Trailing edge: the closed option ends at exactly zero thickness (to 10−16); the open option leaves the expected 0.25 % gap on a 12 % section.
  • Browser and MATLAB agree to within 5×10−7 of chord for 0012, 2412 and 4415, the rounding limit of the exported files.

These checks also caught bugs in the first MATLAB version: the camber line used its front equation along the whole chord, the slope equation used thickness where it should have used \(x\), the upper surface took the cosine of \(x\) instead of \(\theta\), and the export copied the upper surface’s heights onto the lower surface. Reading the code as a number also turned 0012 into 12. Together these put a 2412’s upper surface up to 2.5 % of chord out. All are fixed in both versions.

Future developments

  • Full-cosine spacing option. Spacing points with \(x = \tfrac{1}{2}(1 - \cos\beta)\) clusters them at the tail as well as the nose. Worth adding: a one-line change that improves trailing-edge detail for CFD meshes.
  • Rib export for laser cutting. An SVG or DXF outline at true scale, with spar slots, would take a model builder straight from code to cut parts. Worth adding: it removes the CAD step for the main audience.
  • 5-digit series. Adds reflexed sections suited to flying wings. Useful, but it needs the tabulated camber constants, so it is a bigger job than the other two.
  • Built-in lift and drag. Not necessary: XFOIL and XFLR5 already do this well and read the exported file directly.
